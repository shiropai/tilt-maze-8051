> 這份文件由「聊天端 Claude」（claude.ai 的「微處理機」Project）維護，內容是專題的規格與所有已知的硬體資訊。

## 1. 課程與評分

- 課程：微處理機（實作課，課堂和考試都鼓勵使用 AI）
- 期末專題：8051 或 STM32 二選一 → **選 8051**
  - 理由：課堂上所有感測器的驅動都已經在 8051 上驗證過，可以把時間花在創意和整合
- 評分重點：
  1. **創意性**
  2. **硬體使用的完整性**：用到越多種硬體，而且**每一種都有存在的理由**，分數越高

## 2. 遊戲概念

把整塊板子當成托盤，傾斜它來控制點矩陣上的「小球」走迷宮，從起點滾到終點。
這是課堂「Hourglass 數位沙漏」實驗（MPU6050 + 兩片 8x8 點矩陣）的進階版。

### 玩法
1. 開機顯示標題，揮手（IR 感測器）或按 INT0 開始
2. 水平放置 1 秒做校正（零點）
3. 傾斜板子讓球滾到終點（閃爍的點），撞牆會有短促音效
4. 後面的關卡有「陷阱洞」，掉進去就失去一條命（LED 表示剩餘生命）
5. 每關有倒數時間（七段顯示器），時間到也失敗
6. 過關後 OLED 顯示成績，並透過 UART 傳到電腦端記錄排行榜

### 加分創意（有餘力再做，依優先順序）
- **電腦端自訂迷宮**：從電腦用 UART 傳一張新迷宮給 8051，馬上就能玩
- **可變電阻調靈敏度**：轉旋鈕改變球對傾斜的反應（新手／高手模式）
- **難度隨時間變化**：例如球越滾越快、牆會移動
- **PWM 回饋**：球越接近終點，LED 越亮或蜂鳴器音調越高（「熱感應」提示）

## 3. 硬體使用對照表（評分重點）

| 硬體 | 在遊戲中的用途 | 為什麼需要它 |
|---|---|---|
| MPU6050（I2C） | 讀取傾斜角，轉成球的加速度 | 遊戲的核心控制 |
| MAX7219 + 8x8 點矩陣 ×2 | 16 x 8 的迷宮場地、球、終點 | 主畫面 |
| MAX7219 + 七段顯示器 | 倒數時間、關卡編號 | 不用看 OLED 就能一眼看到時間 |
| OLED SSD1306（I2C） | 標題、選單、關卡資訊、成績 | 文字資訊 |
| UART | 成績傳到電腦、電腦傳自訂迷宮、除錯訊息 | 和電腦互動 |
| External interrupt INT0 / INT1 | 暫停／開始、選關／重來 | 按鍵要立即反應，不能等主迴圈輪詢 |
| Timer0 interrupt | 250 us 時基：計時、軟體 PWM、蜂鳴器音調 | 所有時間相關功能的基礎 |
| PWM（軟體，Timer0 產生） | LED 亮度（生命值、呼吸燈）、蜂鳴器音調 | 標準 8051 沒有硬體 PWM，自己用 timer 做 |
| 蜂鳴器 | 撞牆、掉洞、過關、失敗的音效 | 回饋 |
| LED（P1） | 剩餘生命、暫停狀態 | 狀態指示 |
| IR 感測器（經 MCP3202 ADC） | 揮手開始遊戲 | 非接觸操作 |
| 可變電阻（經 MCP3202 ADC） | 調整靈敏度 | 讓玩家自訂手感 |

> 霍爾感測器、MLX90614 測溫目前沒有用到。若想再加，霍爾感測器 + 磁鐵可以做成「關卡鑰匙」。

## 4. 腳位與資源分配

**所有腳位都定義在 `inc/board.h`，程式其他地方不准寫死腳位。**

| 腳位 | 用途 | 來源／備註 |
|---|---|---|
| P0_0 / P0_1 | I2C SCL / SDA（MPU6050 0xD0、OLED 0x78） | OLED_MPU6050 實驗 |
| P1 | 8 顆 LED（低電位點亮） | Hall_counter 實驗 |
| P2_0 | 序列匯流排 CLK（MAX7219 ×2 組、MCP3202 共用） | IR_sensor 實驗 |
| P2_1 | 序列匯流排 DIN（同上） | IR_sensor 實驗 |
| P2_2 | MCP3202 DOUT（MISO） | IR_sensor 實驗 |
| P2_3 | MCP3202 CS | IR_sensor 實驗 |
| P2_4 | 七段 MAX7219 CS | IR_sensor 實驗（LOAD_MAX） |
| P2_5 | 點矩陣 MAX7219 CS（兩片串接） | **新的接法，待確認** |
| P3_0 / P3_1 | UART RXD / TXD | — |
| P3_2 | INT0：暫停／開始鍵 | — |
| P3_3 | INT1：選關／重來鍵 | — |
| P3_7 | 蜂鳴器 | Hourglass 實驗 |

| 資源 | 分配 |
|---|---|
| Timer0 | mode 2，每 250 us 中斷：1 ms 計數、LED 軟體 PWM（16 階、250 Hz）、蜂鳴器方波 |
| Timer1 | mode 2，UART 9600 baud（**不能拿去做別的**） |
| INT0 / INT1 | 下降緣觸發，ISR 裡用時間戳去彈跳（150 ms） |
| Serial ISR | RX 存進 8 bytes 環形緩衝區；TX 用旗標等待 |
| 中斷優先權 | Timer0 高優先權（聲音和 PWM 才不會抖） |

## 5. 待確認事項（要問使用者或在實機上測）

> **開發環境（2026-11-20 使用者確認）**：編譯、燒錄、實機測試**全部在學校電腦上做**。
> Claude Code 所在的 Mac 沒有 SDCC，只能寫程式和管理 git。以下事項請使用者在學校填 `docs/SCHOOL_TEST.md` 回報。

- [ ] **晶片型號**：AT89S51（4 KB flash、128 B RAM）還是 AT89S52（8 KB、256 B）或其他？
  目前程式碼 4.6 KB，**如果是 4 KB 的晶片就已經超過了**
- [ ] **晶振頻率**：UART 實驗的 TH1 = 0xFD 代表 11.0592 MHz，Hourglass 註解寫 12 MHz；目前假設 11.0592 MHz
- [ ] 點矩陣 CS 能不能接 P2_5？兩片的左右順序（`MATRIX_NEAR_IS_LEFT`）
- [ ] 七段顯示器是 4 位還是 8 位（`SEG_DIGITS`）
- [ ] 蜂鳴器是有源還是無源？（無源才能用 PWM 發出不同音調）
- [ ] 按鍵能不能接到 P3_2 / P3_3？
- [ ] MPU6050 的安裝方向：往右傾時球要往右（`TILT_X_SIGN`、`TILT_Y_SIGN`）
- [ ] 燒錄器型號與燒錄軟體、燒錄指令（之後可以寫成 `make flash`）

## 6. 軟體架構

```
src/
  main.c      遊戲主程式（目前是 M1 硬體整合測試版）
  sys.c       Timer0 時基、軟體 PWM、蜂鳴器、INT0/INT1、UART
  max7219.c   點矩陣（framebuffer + flush）、七段顯示器
  adc3202.c   MCP3202 ADC（IR、可變電阻）
  mpu6050.c   MPU6050 初始化與讀值
  oled_i2c.c  OLED 文字顯示（已改成 burst 寫入，比課堂版快）
  i2c.c       軟體 I2C（課堂版，未修改）
  delay.c     課堂的組語延遲
inc/
  board.h     ★ 所有腳位與硬體參數
  font.h      5x7 字型（A~Z、0~9、部分符號）
```

### 遊戲狀態機（規劃）
```
TITLE ──揮手/INT0──▶ CALIBRATE ──1 s──▶ PLAY ◀──INT0──▶ PAUSE
                                          │
                     ┌────────────────────┼─────────────────┐
                 到達終點              掉進洞／時間到       INT1
                     ▼                    ▼                 ▼
                  CLEAR ──▶ 下一關     FAIL（扣命）       重來本關
                                          │ 命用完
                                          ▼
                                      GAME OVER ──▶ RESULT（OLED + UART）
```

### 物理模型（定點數，不用浮點）
位置與速度用 Q8.8 定點數（高 8 位 = 格子座標，低 8 位 = 格子內的小數位置）。每個 frame（$20\,\text{ms}$）：

$$v_{k+1} = v_k + \frac{\theta_k}{4} - \frac{v_k}{16}, \qquad p_{k+1} = p_k + v_{k+1}$$

- $\theta_k$：加速度計高位元組扣掉零點（$\pm 2g$ 時 $1g \approx 64$）
- $\frac{v_k}{16}$ 是摩擦；速度限制在 $\pm 48$（每個 frame 最多移動 $\frac{48}{256}$ 格）
- 撞牆：該軸速度反向並減半，$v \leftarrow -\frac{v}{2}$
- **兩個軸分開處理碰撞**：先移動 x、檢查牆，再移動 y、檢查牆，球才會沿著牆滑

### 迷宮資料格式（規劃）
- 一關 = 16 bytes 牆壁點陣（和 `matrix_fb` 同格式）+ 起點、終點、陷阱洞座標
- 存在 `__code`（flash），不佔 RAM
- 畫面 = 牆壁 OR 球（球閃爍才看得出來和牆的差別）

### UART 協定（規劃，9600 8N1）
- 8051 → 電腦：`READY`、`START L1`、`CLEAR L1 T=1234`（毫秒數 / 10）、`FAIL L1`、`OVER`
- 電腦 → 8051：`r` 重來、`1`~`9` 選關、`M` + 32 個 16 進位字元 = 自訂迷宮
- 電腦端可以寫一個 Python 小程式（`tools/`）接收成績並顯示排行榜

## 7. 硬體限制（寫程式前一定要知道）

- **RAM**：標準 8051 內部 RAM 只有 128 bytes，堆疊也在裡面。目前全域變數約 80 bytes，堆疊剩約 46 bytes
  - 每次加功能都跑 `make size` 看「Stack starts at」，**堆疊起點不要超過 0x60**
  - 常數表（迷宮、字型、音階）一律加 `__code` 放 flash
  - 不要用指標當函式參數（SDCC 通用指標 3 bytes），不要用 `printf`、`float`、`long`
- **速度**：I2C 是軟體 bit-bang，很慢
  - 讀一個暫存器約 3~4 ms，所以遊戲只讀 X、Y 的高位元組
  - OLED 印一個字約 2~3 ms：**遊戲中每個 frame 只能更新 OLED 的一小部分**，不然會卡
  - 點矩陣和七段是 SPI 式 bit-bang，很快
- **SDCC 規定**：中斷函式的原型要出現在 main.c，所以 main.c 一定要 `#include "sys.h"`
